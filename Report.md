Memory Simulator Report

Initially planning how we wanted to model this simulator came down to us breaking it into several steps which followed the flow of the provided image from the lab spec. This started with us first creating classes for both our TLB and page table. The TLB contained methods such as enqueue for adding to the buffer (and popping if full), lookup for returning an entry if it was a TLB hit, and unload, for evicting frames that got taken out of physical memory. The TLB stored entries inside of a list, which contained python dictionaries representing each and containing the following keys: page, frame, and loaded. The page table had a very similar implementation, using both lookup, unload, and update as methods to perform their respective purpose. Entries for the page table were also stored in a list inside its class. But with entries being hard set at 2^8, we chose to just let the indices of the list represent the page number, and the elements were dictionaries with the following keys: frame, loaded.  

Our other objects were the backing store, physical memory, and the reference sequence. We decided that it would be easiest to just simply use python lists for all three of these. As we could just index the backing store with page number (as each element was 256 bytes from the file), store physical memory as dictionaries inside the list with page and content as the keys, and the reference sequence being a list allowed for easy looping in our page replacement algorithms.  

Now our final functional units are implementing each of the three PRA’s. Up to this point we had already programmed everything with the assumption that pages will not always equal frames. This made programming the PRA’s much easier because our main function handled all adding to physical memory that didn’t require any algorithm. So this allowed for every algorithm to just look at a sequence, where you were in the sequence, what the state of physical memory was, and then make a decision which page to evict based on that. For FIFO, the oldest frame was marked for replacement, and the frame would constantly cycle using mod to make sure it never went out of list bounds. For LRU and OPT, almost identical code was able to be used. We created a list of candidates to be evicted, and then using python slicing on the sequence, went either forward or backward in the sequence and removed any pages from the candidates list that appeared first in the respective direction. Leaving only the final candidate the one to be evicted.

Creating these components was the vast majority of the work. After they were created, following the flow from the labspec was primarily just a matter of method calls on the instances of our objects, error checking any edge cases such as initially empty TLB, or no frame matching to a page yet. Then just looping through and making sure to branch depending on TLB hit/miss, page table hit/miss, and if a fault occurred, deciding whether a PRA was needed or not. The addresses stored in the content of each frame were unpacked using python's struct, converted to hex and used in the final output of the program. The number of page faults and TLB hits/misses were also tracked with simple counters initialized at the start of main, in order to print out the final statistics. After testing with the provided test cases, the modeling and implementation of the memory simulator was complete.
